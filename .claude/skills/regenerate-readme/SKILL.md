## Generation steps

1. Read the sources above and inventory the existing facts against the carryover
   slots below. Resolve discrepancies from source, recording factual corrections.
2. Render help only, using `uv run --frozen omc <cmd> --help` for every command
   described (including `dependency watch`/`list`, `title`, and `shell-integration`).
   `--frozen` avoids rewriting `uv.lock`. Installation examples are output text,
   not commands to execute while generating documentation.
3. Write `README.md` in full using the fixed outline below. The opening four
   user topics should be easy to skim. Section budgets are targets; complete,
   accurate facts and short paragraphs take precedence over a total line target.
4. Check the carryover slots, relative links and anchors, four Mermaid fences,
   option rows against the parser, and the untouched shell document. If a
   defect comes from this recipe, correct the recipe and regenerate its output.
5. Run `uv run --frozen pytest tests/unit/test_cli.py -q -k 'readme or shell_integration_documents'`.
   A guard failure requires correction and another run; these guards do not judge prose.
6. Show `git diff --check` and `git diff -- README.md .claude/skills/regenerate-readme/SKILL.md`.
   Report checks and remaining uncertainties. Committing and publishing belong
   to the enclosing lifecycle, outside this recipe.

## Output contract

Use short paragraphs, numbered install steps, option/reference tables and
readable command blocks. Explain a command's purpose before its details.
Keep exact machine-contract names. Avoid badges, screenshots and GIFs.
Generated `.omc/docs/` is gitignored: explain it without linking to it on GitHub.
Keep the `development` anchor and the shell link. Do not move other retained
facts to a development document or replace them with links.

## Common mistakes to catch before returning

- Dropped facts: compare all slots above with the prior README and source.
  Only the two tab-title paragraphs leave for shell-integration; just recipes,
  golden-path tutorial, variation-writing guide and auth table leave the README
  for their existing references. Fold the former Understanding a codebase
  material into lifecycle/architecture. Retain security and license substance.
- Dense paragraphs to meet a line count: break at topic boundaries; section
  budgets are targets, not a reason to hide facts in a wall of text.
- Unchecked commands or machine names: parser/source win; help is rendering.
- A drift fix only in the output: fix this recipe or its source and regenerate.
- Moving shell prose during regeneration: preserve its verbatim extraction.
